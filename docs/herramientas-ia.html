IA Integrada en la Aplicación (Inferencia en Producción)

El agente utiliza dos modelos de lenguaje de gran escala (LLMs) a través de una API compatible, cada uno especializado en una etapa distinta del flujo de análisis. La combinación de un modelo multimodal (visión) con un modelo de razonamiento lógico (texto) garantiza precisión en la extracción de datos y en la emisión del veredicto clínico.

👁️ Qwen 3.8-27B qwen/qwen3.8-27b

Rol: Motor de extracción documental multimodal (Visión + Texto).
Este modelo recibe directamente los archivos crudos subidos por el usuario (PDFs e imágenes escaneadas) y es capaz de "leer" visualmente el contenido para extraer las entidades médicas y de seguros relevantes.

TipoVision-Language Model (VLM), 27 mil millones de parámetros EntradaImágenes base64 de cada página del documento (PDF renderizado o foto) SalidaJSON estructurado con campos: cédula, póliza, diagnóstico, procedimiento, exclusiones, carencias ¿Por qué?Es el único modelo multimodal disponible en la cuenta que soporta entrada de imágenes para documentos escaneados
🧠 GPT-OSS-120B openai/gpt-oss-120b

Rol: Motor de razonamiento lógico y cross-verification.
Una vez extraídos los datos del informe médico y la póliza, este modelo realiza el cruce inteligente: compara el procedimiento solicitado contra la lista de coberturas, verifica que no haya exclusiones aplicables, evalúa si se cumplieron los períodos de carencia y emite un veredicto fundamentado.

TipoLarge Language Model (LLM), 120 mil millones de parámetros EntradaJSON estructurado con datos del informe médico + datos de la póliza SalidaVeredicto (preaprobado / rechazado / documentos_faltantes), razón detallada y flag de sospecha Configuraciónreasoning_effort: "medium" — balance entre profundidad de análisis y velocidad de respuesta ¿Por qué?Modelo de texto puro sin capacidades web/agentic, lo que evita alucinaciones por búsquedas externas (requisito del plan técnico)

IA para el Ciclo de Desarrollo (Agentic Coding)

Además de los modelos que corren en producción dentro de la aplicación, se utilizaron herramientas de IA avanzada durante todo el ciclo de desarrollo del proyecto:

🤖 Agente Pi (Gentle AI Orchestrator)

Entorno de programación asistida por IA con capacidad de ejecutar código, editar archivos, correr comandos y testear en tiempo real. El agente operó bajo el flujo Organic Driven Development (ODD), un paradigma que estructura el trabajo en tareas incrementales con validación continua.

Tareas realizadasRefactorización de componentes React/Next.js, integración con Notion API, corrección de bugs en producción TestingPruebas end-to-end automatizadas vía Chrome DevTools MCP (navegador real controlado por IA) Code QualityAnálisis estático con TypeScript LSP, ESLint y AST-grep en cada edición HallazgosDetección y corrección de bug de timezone (fechas mostraban un día antes en Panamá UTC-5), problemas de accesibilidad (a11y), y fallo en modelo de IA por token budget insuficiente
🌐 Chrome DevTools MCP

Protocolo que permite al agente de IA controlar un navegador Chrome real de forma programática: navegar páginas, llenar formularios, hacer clic en botones, tomar screenshots y leer la consola de errores. Esto permitió probar el flujo completo de la aplicación (subida de archivos, análisis, historial) sin intervención humana manual, verificando que la UI y el backend funcionan correctamente de punta a punta.

4

Medidas Anti-Alucinación

Se implementaron múltiples capas de protección para garantizar que la IA no invente datos clínicos:

1. Modelos sin acceso a internet: Se descartó intencionalmente el modelo groq/compound-mini (que tiene capacidades de búsqueda web) para evitar que la IA "busque" información médica en internet. Los modelos usados operan exclusivamente sobre los documentos proporcionados por el usuario.

2. Validación de esquema estricta: El JSON devuelto por la IA se valida contra un esquema exacto de 16 campos tipados (strings, arrays, records). Si la estructura no coincide, el caso se rechaza antes de emitir cualquier veredicto.

3. Cross-verification en dos fases: La extracción (Fase 1, modelo de visión) y la evaluación (Fase 2, modelo de texto) usan modelos completamente distintos. Esto crea una verificación cruzada natural donde el segundo modelo valida la coherencia de lo que extrajo el primero.

4. Flag de sospecha automático: Si la IA detecta inconsistencias entre los documentos (ej: la cédula del informe no coincide con la de la póliza), marca el caso como "sospechoso" para revisión manual humana, en lugar de emitir un veredicto automático.
5

Técnicas de Prompt Engineering y Formateo

El éxito de la automatización clínica no solo depende del modelo, sino de cómo se estructura la consulta y la respuesta esperada:

1. System Prompts Clínicos: Se diseñó un contexto restrictivo que obliga al modelo a actuar como un "auditor médico estricto". Se le instruye explícitamente: "No asumas información. Si un dato no está en el texto proporcionado, devuelve null o un arreglo vacío".

2. Forzado de Esquema JSON (JSON Mode): En lugar de respuestas de texto libre, se utiliza una instrucción fuerte para que el LLM devuelva la información mapeada exactamente a una interfaz de TypeScript predefinida de 16 propiedades. Esto permite conectar la salida de la IA directamente con la base de datos sin parseos propensos a fallos.

3. Estrategia de Fallbacks y Retries: Se implementó un algoritmo resistente a fallos en la capa de conexión con Groq. Si la IA devuelve un formato inválido o sufre un timeout, el sistema captura el error y reintenta la consulta automáticamente (hasta 2 veces) usando modelos de respaldo.
6

Infraestructura de Inferencia y Persistencia

La capa de inteligencia artificial se apoya en herramientas de infraestructura de última generación para garantizar respuestas en tiempo real:

⚡ Groq LPU Inference Engine

El ruteo hacia los modelos se realiza a través de la infraestructura de inferencia ultra-rápida de Groq. Dado que el análisis requiere leer documentos largos (informes médicos y pólizas enteras), la velocidad de procesamiento de tokens es crítica para no bloquear la experiencia del usuario (UX).

📓 Notion API (Vector / Record Storage)

Funciona como la capa de persistencia y memoria del sistema. Cada veredicto emitido por la IA se archiva inmediatamente con un cruce de 18 columnas de metadatos clínicos. Además, se utiliza la Notion File Upload API para adjuntar las pruebas documentales originales (PDFs) junto al veredicto de la IA, creando una pista de auditoría inmutable.
